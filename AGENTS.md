# Работа над калькулятором свободного времени

## Главный порядок работы

- Сначала довести сам продукт до законченного состояния и показать его владельцу для проверки. К продуктовому анализу, событиям, метрикам, backend и сбору данных переходить только после явного принятия продукта владельцем.
- Следовать выбранной концепции G3 «Фисташковые карточки» из `design/mockups/concept-g3-pistachio-cards.png` и `docs/design-system.md`. Макет задаёт композицию и характер интерфейса; числа и конкретные занятия на картинке иллюстративны.
- Интерфейс должен выглядеть как продуманный человеческий продукт: ясные русские подписи, спокойная зелёная палитра, плотная иерархия, минимум повторов, без декоративных фраз и бессмысленных элементов.
- Не усложнять проект: текущий MVP работает в браузере, без аккаунтов и сервера.

## Обязательные сценарии продукта

- Семь карточек дней показывают реальные занятия, их длительность и свободное время после расчёта. Выбор карточки раскрывает подробный план этого дня.
- На телефоне показывать компактный ряд переключателей дней и одну раскрытую карточку выбранного дня.
- Подробный план показывает цветные блоки на шкале времени; по блоку можно открыть редактирование. Ночной переход и дорога отражаются в тех сутках, куда попадают минуты.
- Если интервалы пересекаются, оба блока должны оставаться видимыми и обе записи — доступными для редактирования.
- У категорий разные разумные значения времени по умолчанию: сон 23:00–07:00, работа 09:00–18:00. При выборе другой категории обновляются только поля, которые пользователь ещё не менял вручную.
- Ручное время не сбрасывается при переключении категории. Типичный сон сразу выбран на каждый день, работа и учёба — на будни; доступны быстрые варианты «Этот день», «Будни» и «Каждый день».
- Для офлайн-занятия время дороги обратно сначала повторяет введённое время туда. Обратную дорогу можно затем изменить отдельно.
- Редактирование повторяющейся записи из конкретного дня меняет только этот день. Новый сон заменяет существующий сон для выбранных дней и не создаёт дубликат.
- Онлайн-занятие может пересекаться с другими занятиями и дорогой. Допустимое пересечение выделяется жёлтым, а общие минуты учитываются только один раз по правилам `docs/calculation-rules.md`.
- Недопустимое пересечение проверяется при сохранении занятия: показывается одна понятная ошибка в форме, запись не добавляется.
- У категорий должны быть небольшие различимые иконки рядом с названиями в карточках и форме.
- Расчёт корректно обрабатывает пустую неделю, пересечения, переход через полночь, дорогу и повторный расчёт после правок. Ошибки не должны скрывать введённые занятия.
- В свободное время входят только непрерывные промежутки строго больше 30 минут; пауза ровно 30 минут не входит.
- Расписание хранится только в браузере; точные интервалы и названия не передаются на сервер.

## Проверка изменений

- Перед отправкой изменений на GitHub проверить сборку, тесты расчёта и ключевые сценарии в браузере на компьютере и телефоне.
- После изменений интерфейса визуально сравнить снимки экрана с G3 и проверить, что текст читается, блоки времени не накладываются друг на друга, а страница не прокручивается по горизонтали.
- Владелец проекта принимает продукт сам. Не обозначать этап продукта завершённым до его проверки и согласия.
- После принятия продукта аналитические определения, SQL, выводы и гипотезы пишет владелец; агент может объяснять принципы, проверять решения и реализовывать согласованные технические изменения.
