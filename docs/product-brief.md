# Описание продукта: Калькулятор свободного времени

## Задача и пользовательский сценарий

Человеку бывает трудно оценить, сколько времени действительно остаётся в типичной неделе после сна, работы, учёбы, других дел и поездок. Пользователь заполняет расписание по дням недели, добавляет активности и получает занятое и свободное время по дням и за неделю, а также структуру занятости по категориям.

Для активности нужны категория, дни, время начала и окончания, формат online/offline и, если требуется, дорога туда и обратно. Для online-активности время дороги равно нулю. Сон, работа и учёба также задаются временем начала и окончания. Повторяющиеся занятия должны вводиться без повторного создания отдельной записи для каждого дня.

## Минимальный расчёт для MVP

- Неделя состоит из семи суток по 24 часа; расчёт ведётся в минутах.
- Занятое время образуют интервалы сна, работы, учёбы, прочих активностей и дороги. Свободным считается непрерывный незанятый промежуток строго больше 30 минут; недельный итог — сумма семи дневных итогов.
- Результат показывает занятое и свободное время по каждому дню и за неделю, а также распределение занятого времени по категориям. После правки расписания расчёт можно повторить.
- Точные интервалы расписания обрабатываются в браузере. В будущую аналитику они не передаются.

Расчёт «реально доступного» свободного времени с учётом слишком коротких промежутков — отдельное развитие продукта после базового MVP.

## Правила расчёта перед реализацией

Для MVP приняты [однозначные правила расчёта](calculation-rules.md). Они задают поведение пересечений, переходов через полночь и дороги. Ниже сохранены причины, по которым эти случаи требуют отдельной проверки.

1. **Пересечения.** Они считаются ошибкой ввода: так занятые минуты не дублируются, а распределение категорий остаётся однозначным.
2. **Переход через полночь.** Окончание раньше начала означает следующие сутки; интервал делится по дням, в том числе на границе повторяющейся недели. Равные времена недопустимы.
3. **Дорога.** «Туда» занимает время непосредственно перед offline-активностью, «обратно» — непосредственно после неё. Для online-активности оба интервала отсутствуют.

Эти решения влияют на результат и включены в спецификацию; их нужно проверить тестами калькулятора.

## Граница аналитики и приватность

Этот документ не определяет метрики, event schema, воронку, SQL или гипотезы: их автор проекта разработает самостоятельно на следующих этапах. Потенциально полезны обезличенные события взаимодействия и агрегаты длительностей, но состав данных утверждается отдельно. Не собирать ФИО, контакты, точную геолокацию, fingerprint или постоянный идентификатор пользователя; не сохранять точное расписание на сервере.
